## Purpose

Dr.Exam is a desktop proctoring application purpose-built for Windows 11. It solves the problem of remote exam supervision by providing invigilators with automated tools — face detection, gaze tracking, screen recording — while keeping all sensitive data on the candidate's machine. It is intended for educational institutions, certification bodies, and any organization that needs to administer proctored exams remotely.

## Features

- **Face Detection** — Real-time detection using YOLOv8. Tracks multiple faces, verifies presence, and logs absences automatically.
- **Gaze Tracking** — Gaze estimation via MediaPipe. Detects when a candidate looks away from the screen and flags suspicious behavior.
- **Screen Recording** — Automated screen capture with timestamped logs. Every second of the exam is recorded for offline review and audit trails.
- **Proctor Dashboard** — Real-time monitoring dashboard with live alerts. Color-coded risk indicators for all candidates at a glance.
- **Offline Mode** — Works without internet. All proctoring data is stored locally and syncs automatically when connectivity is restored.
- **Privacy First** — All processing is on-device. No cloud uploads, no video streaming. Data stays on the machine.
- **Responsive Marketing Site** — Landing page with capabilities overview, privacy policy, and terms & conditions. Mobile-friendly with animated scroll effects.

## Architecture

### Overall Design

The repository contains a **marketing website** (Angular single-page application) that serves as the public face for the **Dr.Exam desktop application**. The desktop app itself is a separate binary distributed via GitHub Releases (`DrExam.zip`). The Angular app is the front door: it explains the product, links the download, and hosts legal pages.

### Frontend Architecture

- **Standalone components only** — No `NgModule` in the entire codebase.
- **Lazy-loaded routes** — Each of the three feature pages (`home`, `privacy-policy`, `terms-conditions`) is a separate chunk loaded on demand via `loadComponent`.
- **Eager layout** — `NavComponent` and `FooterComponent` are eagerly imported by `App` (they are not routes).
- **Angular 18+ control flow** — `@if` / `@for` would be used if iteration were needed (none present in current templates, but convention is established).
- **CSS-based design system** — No UI library. Typography uses three Google Fonts (Archivo Black, Work Sans, Space Mono). Colors are `#0A0A0A` (black), `#FAFAFA` (white), `#EF4444` (red accent). Border radius is `0px` throughout. Shadows are `none`.

### Request / Response Flow

```
User enters URL
  → index.html served from Vercel
  → main.ts bootstraps App component
  → Angular Router matches the URL path
  → loadComponent fetches the feature chunk (JS)
  → RouterOutlet renders the component inside <main>
  → User navigates → router updates without full page reload
```

### Scroll Animation Flow

```
Page loads with AnimateOnScrollDirective on <section>
  → Directive checks if the element is already in the viewport
    → If yes: adds `is-visible` immediately
    → If no: adds `will-animate` (opacity: 0, translateY: 20px)
      → Creates IntersectionObserver with threshold 0.1
      → On intersection:
          → Removes `will-animate`
          → Adds `is-visible` (opacity: 1, translateY: 0)
          → Disconnects observer (one-shot)
```

## Core Components

### `App` (`src/app/app.ts`)

- **Responsibility**: Root component. Lays out the application shell: nav bar at top, router outlet in the middle (flex-fill), footer at bottom, and a floating go-to-top button.
- **Dependencies**: `RouterOutlet`, `NavComponent`, `FooterComponent`, `GoToTopComponent`.
- **Template** (`app.html`): Six lines — `<app-nav />`, `<main><router-outlet /></main>`, `<app-footer />`, `<app-go-to-top />`.

### `NavComponent` (`src/app/layout/nav/nav.component.ts`)

- **Responsibility**: Sticky top navigation bar with links to Home, Privacy Policy, and Terms & Conditions. Responsive: on mobile (≤768px) the links collapse behind a full-screen overlay toggled by a hamburger button.
- **States**: `menuOpen` boolean toggles the mobile menu. Menu closes on link click, overlay click, or route change (via `closeMenu()`).
- **Dependencies**: `RouterLink`, `RouterLinkActive` for active link highlighting (red bottom border on desktop, red text on mobile).

### `FooterComponent` (`src/app/layout/footer/footer.component.ts`)

- **Responsibility**: Site footer with navigation links and copyright notice.
- **Dependencies**: `RouterLink`.
- **Template**: Three links (Home, Privacy Policy, Terms & Conditions) and a copyright line. Mobile layout uses a 2-column grid.

### `GoToTopComponent` (`src/app/shared/components/go-to-top.component.ts`)

- **Responsibility**: Fixed-position button that appears when the user scrolls past 200px. Smooth-scrolls to the top on click. Uses inline template and styles (no separate HTML/CSS files).
- **Inputs/Outputs**: None. Uses `@HostListener('window:scroll')`.
- **States**: `visible` boolean controls the `visible` CSS class.

### `AnimateOnScrollDirective` (`src/app/shared/directives/animate-on-scroll.directive.ts`)

- **Responsibility**: Adds scroll-triggered entrance animations to any element with the `[animateOnScroll]` attribute. On intersection the element transitions from `will-animate` (hidden, offset) to `is-visible` (shown, reset).
- **Implementation**: Uses `IntersectionObserver` with `threshold: 0.1`. One-shot — disconnects after first intersection. Falls back to immediate visibility if the element is already in the viewport on init.

### Feature Pages

All three feature pages (`HomeComponent`, `PrivacyPolicyComponent`, `TermsConditionsComponent`) are structurally identical patterns:

- Import `AnimateOnScrollDirective`
- Each has a separate `.html` and `.css` file

## How It Works

1. **A visitor lands on the marketing site** (hosted on Vercel). The Angular app boots in the browser.
2. **The nav bar** sticks to the top. On mobile, it collapses into a hamburger menu with a full-screen animated overlay.
3. **The home page** loads via lazy chunk. The hero section displays the Dr.Exam logo, a tagline, and a download button for the desktop app. Both hero elements and the capabilities grid below fade in with staggered scroll animations powered by `AnimateOnScrollDirective`.
4. **The capabilities grid** shows six cards describing the desktop app's features: face detection, gaze tracking, screen recording, proctor dashboard, offline mode, and privacy-first architecture. Cards enter sequentially with increasing delay.
5. **Navigation** between pages (Home, Privacy Policy, Terms & Conditions) is handled by the Angular Router without full page reloads — each page is a lazy-loaded chunk fetched on demand.
6. **The download button** points to a GitHub Release (`v1.0.0/DrExam.zip`). When a user downloads and runs the desktop app on Windows 11, the proctoring tools (YOLOv8 face detection, MediaPipe gaze tracking, screen recording) run entirely on-device.
7. **Legal pages** provide the privacy policy and terms & conditions for the desktop service, both effective July 25, 2026.
8. **The go-to-top button** appears after scrolling 200px and smooth-scrolls back up when clicked.
